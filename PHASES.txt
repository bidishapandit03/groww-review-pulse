GROWW REVIEW PULSE — PHASE PLAN (1-9)
=====================================
Stack: Next.js + TypeScript on Vercel (PRD Option C). All phases committed to git
on `main`. Raw review data is NEVER committed (lives in Vercel Blob in prod,
data/raw/ locally — both gitignored).

========================================================================

DONE — PHASE 2: Import reviews (PRD Step 2)
========================================================================
Goal: Pull public reviews from both stores into one normalized corpus and
accumulate enough history to reach the 8-week window.
Commit: bebe62e "feat(import): fetch reviews from both public stores"

Built:
- lib/imports/appstore.ts — Apple public customer-reviews RSS (India store,
  app id 1404871703), up to 10 pages x ~50, newest only. Author field is
  deliberately never read.
- lib/imports/playstore.ts — google-play-scraper (public pages, no login),
  package com.nextbillion.groww, newest sort, up to ~2000 reviews.
- lib/imports/index.ts — orchestrator. Refactored (phase 3) into PURE
  functions so each pipeline step can own its own state:
    * fetchFreshReviews() -> Review[]   (fetch both stores in parallel,
                                           allSettled, throw only if both fail)
    * mergeCorpus(existing, fresh)      (dedup by id, fresh data wins)
    * sliceWindow(corpus, weeks)        (filter to WindowResult with per-store
                                           coverage = oldest date)
- scripts/smoke-import.ts — manual diagnostic: fetch -> merge -> slice 8 weeks,
  prints counts, coverage, oldest/newest 3.

Data lives at: data/raw/pipeline/corpus.json (local) or Blob key pipeline/corpus.json (prod).
Observed coverage: ~2.5 weeks back (public stores cap what they expose), so the
corpus grows with each weekly run toward the 8-week window.

DONE — PHASE 3: Clean data and redact PII (PRD Step 3)
========================================================================
Goal: Mask user-identifying details before anything reaches an LLM, a store,
or a file. PII handling is a product requirement (PRD G3), not an afterthought.
Commit: dab8662 "feat(redact): clean & redact PII with CI gate"

Built:
- lib/redact.ts — idempotent masking:
    redactText(text)   — mask URLs, www links, emails, +91 phones, plain 10-digit
                          Indian mobiles, spaced phones, PAN, Aadhaar groups,
                          12+ digit runs, UPI IDs, @handles -> "[REDACTED]".
    containsPii(text)  — detection patterns + extra spacing variants.
    redactReview / redactReviews — mask title+text, drop reviews with no
                          content left.
- tests/redact.test.ts — 21 cases incl. idempotency, clean-text passthrough,
  mask-literal safety. Passing.
- scripts/pii-gate.ts — scans tracked data/sample + outputs for residual PII;
  exits non-zero on any hit.
- .github/workflows/ci.yml — CI on push/PR: npm ci --legacy-peer-deps, typecheck,
  vitest, pii:gate.
- vitest.config.ts -> vitest.config.mts migration.
- package.json — scripts: test, test:watch, typecheck, lint, pii:gate.
- lib/pipeline/types.ts — shared pipeline types & storage keys:
    CORPUS_KEY, STATE_KEY, TAGGED_KEY, AGGREGATE_KEY, NOTE_KEY,
    PipelineState (runId, step, meta, lastError), pipelineRunSchema,
    AggregateResult, CandidateQuote.

- Write outputs/weekly-note-YYYY-WW.md + NOTE_KEY (pipeline/note.json).

Output: validated weekly note + markdown artifact.

Open decisions: tone (neutral-factual vs urgent)? name an owner + metric per
action idea? include a one-line WoW comparison (must stay within word limit)?

========================================================================
CROSS-CUTTING ENGINEERING CONVENTIONS (from AGENTS.md)
========================================================================
- Pipeline steps = independent functions in lib/; endpoints in
  app/api/pipeline/[step]/route.ts; orchestrator in app/api/cron/pulse/route.ts.
- State via lib/state.ts (Blob in prod, local JSON in dev).
- All external contracts validated with zod.
- ALL prompt text lives in prompts/*.txt (never inline in code).
- Tests in tests/, run with Vitest (npm test). Redaction + validation tests are
  a CI gate.
- Anything exact (counts, averages, WoW change, word count, quote text) is
  computed in code, never by the LLM.
- No PII ever: usernames, emails, phone numbers, IDs, PAN, UPI IDs, URLs,
  12+ digit runs. Redact before any LLM call or file write.
- Secrets only in Vercel env / .env.local; .env.example documents names, never values.
- Screen real value: NEVER commit raw reviews; raw data lives in Blob (data/raw/ locally).
